# Findings from the Phase 2a baseline

What the Phase 2a evaluation found about the Phase 1 system with the v1 models (`qwen2.5-coder:7b`, `all-MiniLM-L6-v2`).
Evidence: `eval/results/20261127T095143-phase1-4fc1921.json` and the analysis in `eval/reports/2a_baseline.md`, which
also lists the limits of the gold set (22 gold includes, 2 of them in topic 3; model labels with a 21-paper human check;
29 extraction fields on 6 papers).

The fix column follows `docs/plan_v2.md`. Phase 2b starts with the agent review, in which the project owner decides
which of these fixes are adopted, so a phase here is a plan, not a decision. Backlog numbers refer to
`docs/backlog.md`.

| # | What we found | Evidence | Planned fix phase |
| --- | --- | --- | --- |
| F1 | **Screening accepts almost everything.** It tests topical fit but not each criterion: study type, population, data level and outcome are ignored. | 52 of 60 papers included. Include recall 22/22, exclude recall 8/36 (22%), hard errors 28/58 (48%): t1 0/9 excludes found, t2 1/10, t3 7/17. 7 of its 8 exclusions are "subject is not mobile money". None of the 52 included papers lists a matched exclusion criterion. The 28 wrong includes fail these checks: not a primary study 12, outcome 6, single agent 4, and others. | Phase 2b: agent review of the screening prompt and output schema, then the model benchmark |
| F2 | **Nothing downstream filters what screening lets through.** Search returns the same kinds of papers, so wrong papers reach extraction. | Search precision@10 is 12/30 (40%): 7/10, 3/10, 2/10. Of the 18 non-relevant slots, the failed checks are mostly study type (5), data level (4), outcome (3), single agent (3) and subject (3); 2 are duplicate copies of a study. | Phase 2b: search review (subfield filter is a plan task; query construction and duplicates are proposals) |
| F3 | **Search returns few papers and mostly preprints.** | 19, 25 and 15 papers for 25 requested (17 in a later run of topic 1). 29 of 30 top-10 papers come from preprint or repository servers. The cause was not tested; the search keeps only papers with a PDF link. | Phase 2b agent review (search) |
| F4 | **One third of the gold includes cannot be downloaded.** The DOI fallback rescues none of them. | 7 of 22 gold includes have no retrievable PDF: t1 6 of 11, t3 1 of 2, t2 0 of 9. Three returned HTTP 403, three an HTML page, one has no URL. Single attempt, 2026-11-27 (backlog #40). | Phase 2b agent review (ingestion: other OpenAlex locations) |
| F5 | **Retrieval misses the passage that holds the answer.** | The gold quote is in the 5 retrieved chunks for 6 of 29 fields (21%); task and main_findings 0 of 12. 11 of the 23 misses are quotes on pages 1 and 2; a 59-page paper missed all 5 fields; 3 misses retrieved the right page but not the quote. | Phase 2b: chunk overlap, keyword plus vector search, reranker (each adopted only if recall@5 or faithfulness improves); full-paper experiment |
| F6 | **Extraction reports values it was not shown evidence for, and their correctness is unmeasured.** | 25 of 29 gold fields reported found (86%), but the gold passage was in the context for only 5 of them. 2 method values are just "empirical study"; the task of all 3 t2 papers restates the review question. Whether the values are right needs the faithfulness judge. | Phase 2b: faithfulness judge on the saved baseline outputs (required); extraction with field status and evidence (chunk, page) |
| F7 | **The pipeline cuts extraction prompts silently.** Ollama's default context keeps about 2,050 tokens. | The largest extraction-gold paper needs 8,860 tokens, Ollama reported 2,050: about 77% lost, no error. The baseline ran with a 16,384 context, so it shows extraction better than the production pipeline, which still uses the default (backlog #38). | Phase 2b: set the context length for the pipeline (agent review) |
| F8 | **Extraction dominates the run time.** | 98.8 s per paper for retrieval and extraction against 23.7 s per paper for screening. Latency budget 1,640.5 s (27.3 min), 62% of it extraction. One smoke run of topic 1 through the API took 3,093 s (51.5 min) for 17 papers screened and 13 extracted, with extraction at 194 s per paper. | Phase 2b: parallel extraction, full-paper experiment, model benchmark (all measured against the budget) |
| F9 | **Screening is deterministic, so the baseline noise is zero and the paired model-selection rule cannot be met.** | 0 flips of 60 between two passes; identical reasoning text for 60 of 60 (`temperature=0`). The baseline already includes all 22 gold includes, so a candidate cannot win a single gold include and the rule's wins − losses ≥ 2 is unreachable. N would be 2 (the floor). | Before the Phase 2b screening benchmark: the author amends the rule in `docs/designs/eval.md` (for example by counting gold excludes found) |
| F10 | **The model never answers `uncertain`.** Backlog #37 (uncertain papers are lost downstream) cost nothing in the baseline. | 0 of 60 decisions `uncertain`; 0 of 22 gold includes marked `uncertain`. Both gold `uncertain` papers were included. | Phase 2b agent review: decide whether #37 still needs a fix |
| F11 | **The API can stall while a run is in progress.** The Streamlit frontend polls the same endpoint. | In the smoke run, `GET /status/{job_id}` did not answer within 30 s during extraction; the run itself finished. Seen once, cause not investigated. | Phase 2b agent review to check it; Phase 3 replaces polling with SSE (backlog #21) |
